# Homework 1

## Среда и воспроизведение

Измерения выполнены 26.09.2026 на NVIDIA GeForce RTX 5070 (12 ГиБ), Windows, драйвер 610.62. Python 3.14.2, PyTorch 2.14.0+cu130 (CUDA 13.0), NumPy 2.5.3, pandas 3.0.6, SciPy 1.18.1, Matplotlib 3.11.2.

Из корня проекта: `make sync`, затем `make hw1`. Последняя команда измеряет сеть, подбирает параметры и строит графики; уже записанные точки пропускаются. Для полного нового прогона задайте новые пути через переменные Makefile `MEASUREMENTS`, `KERNELS`, `THETA` и `FIGURES`. Проверка кода — `make lint`.

На этой карте исходная сетка без ограничения памяти помещается целиком. Чтобы проверить обработку OOM, для всех конфигураций перед созданием модели установлен лимит аллокатора PyTorch 4 ГиБ (`torch.cuda.set_per_process_memory_fraction(4 GiB / total VRAM)`). Это внешняя программная квота, а не исчерпание физических 12 ГиБ. Её можно изменить через `MEMORY_LIMIT_GIB`, но результаты при разных лимитах нельзя смешивать в одном CSV.

## Протокол

Сетка из задания: 11 размеров изображения × 12 batch size = 132 точки. При seed 42 дополнительные размеры — 48, 112, 448, 496; batch size — 65, 70, 78. Каждая пятая точка после перемешивания отложена для проверки (27 точек). Входы — случайные FP32-тензоры; `eval()` и `inference_mode()`, cuDNN benchmark и TF32 отключены.

После трёх прогревочных проходов latency измеряется как медиана синхронизированных проходов за не менее одной секунды. Память — `torch.cuda.max_memory_allocated()` за один проход; energy — прирост счётчика NVML для всей видеокарты, делённый на число проходов. CUDA-ядра профилируются отдельно, чтобы профилировщик не влиял на замеры.

## Результаты и обсуждение

Из 132 точек 130 завершились. `(S=496, B=256)` и `(S=512, B=256)` дали `torch.cuda.OutOfMemoryError`; формула памяти предсказывает для них 3.05 и 3.25 ГиБ при квоте 4 ГиБ. Она не учитывает рабочие буферы CUDA/cuDNN и занижает реальный пик: медианная относительная ошибка по успешным точкам — 67.0%. Для OOM-точек latency и energy не подменяются прогнозом.

Параметры подогнаны по 103 успешным обучающим точкам. На 27 отложенных точках медианная относительная ошибка составляет 2.4% для latency и 5.7% для energy. При малой нагрузке заметен постоянный член `t0`, при большой — вычислительный член. Отдельный memory-bound режим здесь трудно выделить: FLOPs и объём передаваемых данных растут вместе. Энергия включает фоновое потребление всей GPU, поэтому её коэффициенты не следует трактовать как независимые физические затраты.
